# 런타임 구조 위험

이 문서는 Goondan 런타임에서 메시지나 작업의 손실·중복, 실행 정체와 자원 누적을 만들 수 있는 구조를 기록한다. 열린 위험은 현재 코드의 근거, 실패 시나리오와 보완 방향을 담고, 수용한 위험은 설계가 감수하는 내용과 호스트가 지켜야 할 조건을 담는다. 코드나 규격을 바꿀 때 근거 줄과 상태를 함께 확인한다.

## 읽는 법

| 표시 | 뜻 |
|---|---|
| 상태 `남음` | 현재 설계에서 실패 시나리오가 성립한다. |
| 상태 `부분 해결` | 보호 장치가 있으나 남은 경로에서 실패 시나리오가 성립한다. |
| 상태 `수용` | 위험을 현재 설계의 제약으로 감수한다. 호스트가 지켜야 할 조건을 함께 기록한다. |
| 상태 `수용(설계 의도)` | 해당 동작이 제품의 설계 의도다. 호스트가 운영 정책으로 통제할 범위를 함께 기록한다. |
| 상태 `해결됨` | 현재 설계에서는 실패 시나리오가 성립하지 않는다. 회귀 조건을 함께 기록한다. |
| 시점 `단기` | 단일 프로세스나 보통의 사용량에서도 드러날 수 있다. |
| 시점 `규모 확대 시` | 워커 수, 트래픽, 실행 시간이나 저장 데이터가 늘 때 드러난다. |

아래 목록은 심각도 순이다. 해결된 위험은 현재 보호 장치를 보존할 수 있도록 마지막 표에 모아 둔다.

## 열린 위험과 수용한 위험

### 1. 비가역적인 부수 효과는 저널 재생만으로 확정할 수 없다

상태 `수용` · 시점 `단기` · 범위 TypeScript, Python

현재 설계에서 감수하는 내용

일치한 route는 동시에 실행되며, 한 분기가 실패해도 다른 분기가 이미 만든 외부 부수 효과를 되돌리지 않는다(`packages/core/src/runtime.ts:559`, `packages/core/src/runtime.ts:1666`, `python/goondan/goondan/runtime.py:2060`). 승인 작업도 실행 시작을 저널에 기록한 뒤 외부 도구를 호출한다. 프로세스가 외부 호출 성공과 완료 기록 사이에서 종료되면 복구 결과는 `execution_interrupted`이며, 외부 시스템에서 실제로 처리되었는지는 런타임이 판정할 수 없다(`packages/core/src/runtime.ts:2024-2082`, `python/goondan/goondan/runtime.py:734-766`).

호스트가 알아야 할 점

비가역적인 도구는 `turnId`, `operationId` 또는 업무 도메인의 안정적인 키로 중복 실행을 제거한다. 여러 분기가 모두 성공한 뒤 실행해야 하는 부수 효과는 별도의 확정 단계에 두고, 결과가 불명확한 승인 작업은 외부 시스템의 처리 기록과 대조한다.

### 2. JSONL 저널은 세션이 커질수록 재생 비용이 커진다

상태 `남음` · 시점 `규모 확대 시` · 범위 TypeScript CLI

근거

CLI의 `FileJournalStore`는 `append`, `scan`, `head`에서 세션 파일 전체를 읽는다. 추가할 때에도 기존 이벤트를 모두 재생해 현재 상태를 확인한 뒤 JSONL 행을 덧붙인다(`packages/cli/src/chat/session.ts:125-194`, `packages/cli/src/chat/session.ts:278-285`). fold는 스냅샷 이벤트를 읽을 수 있지만, CLI 저장소는 스냅샷 생성이나 파일 압축을 수행하지 않는다(`packages/core/src/fold.ts:266-317`).

실패 시나리오

오랫동안 유지한 세션의 이벤트 수가 늘면 입력 하나를 추가하거나 현재 머리를 확인하는 시간과 메모리 사용량도 함께 늘어난다. 프로세스가 시작될 때 긴 저널을 재생하는 동안 세션 복구와 승인 작업 조회가 지연될 수 있다.

보완 방향

운영용 저장소는 `scan`의 `fromSeq`와 `limit`을 실제 페이지 조회로 구현하고, 순번·펜싱 토큰·`writeId`의 의미를 보존하는 스냅샷과 압축 정책을 둔다. CLI를 장기 세션에 사용할 때에는 파일 바이트 수, 이벤트 수와 재생 시간을 관측하고, 호스트의 보존 정책에 따라 `sessions.delete`를 호출한다.

### 3. 비동기 훅 결과는 나중의 입력 문맥에 붙을 수 있다

상태 `수용` · 시점 `단기` · 범위 TypeScript, Python

현재 설계에서 감수하는 내용

비동기 훅은 현재 값을 복사해 백그라운드에서 실행하고 모델 진행을 막지 않는다. 완료된 결과는 예약 순서를 유지하면서 다음 안전 지점에 메시지로 추가되며, 실행이 먼저 끝나면 같은 인스턴스의 다음 실행에서 적용될 수 있다(`packages/core/src/runtime.ts:1267-1354`, `python/goondan/goondan/runtime.py:1105-1144`). 따라서 오래 걸린 검색이나 계산 결과가 원래 입력보다 뒤의 사용자 입력과 함께 모델에 전달될 수 있다.

호스트가 알아야 할 점

현재 입력의 정확한 값이 필요한 검증, 권한 판정과 요청 변환은 동기 훅으로 구현한다. 비동기 검색 결과에는 질의 키와 자료 버전을 포함하고, 훅 또는 확장 코드가 현재 문맥에 맞는 결과만 추가하며 중복을 제거한다. 운영 관측에는 훅별 완료 시간과 적용 지연을 포함한다.

### 4. stateful fan-in은 가장 느린 출발 실행이 끝날 때까지 입력을 보관한다

상태 `수용` · 시점 `단기` · 범위 TypeScript, Python

현재 설계에서 감수하는 내용

stateful fan-in은 출발 집합의 실행과 대기 입력이 모두 끝날 때까지 도착한 입력을 보관한 뒤 route 선언 순서로 합친다. 런타임은 fan-in 대기 시간, 메시지 수와 입력 크기에 별도 상한을 두지 않는다. 가장 느린 출발 실행이 끝나지 않으면 대상 에이전트도 시작하지 않는다(`packages/core/src/runtime.ts:617-747`, `python/goondan/goondan/runtime.py:2060-2255`).

호스트가 알아야 할 점

호스트는 모델 어댑터와 도구에 취소 가능한 시간 제한을 두고, 런타임에 전달하기 전후의 메시지 수·바이트 수·토큰 추정치를 제한한다. 운영 관측에는 인스턴스별 대기 입력 수와 가장 오래된 대기 시간을 포함한다.

### 5. 동기 대기 순환 검사는 런타임이 아는 실행 관계만 다룬다

상태 `부분 해결` · 시점 `단기` · 범위 TypeScript, Python

현재 보호 장치와 남은 범위

에이전트 도구, 훅의 `agent`와 `agents.run`이 출력을 기다릴 때 런타임은 실제 실행 사이에 대기 간선을 추가하고, 새 간선이 순환을 만들면 입력을 넣기 전에 거부한다(`packages/core/src/runtime.ts:1461-1528`, `python/goondan/goondan/runtime.py:1450-1478`). 도구나 함수가 외부 서비스를 동기 호출하고, 그 서비스가 다른 Goondan 런타임이나 세션을 다시 호출하면서 생기는 대기 관계는 이 그래프에 나타나지 않는다.

호스트가 알아야 할 점

외부 시스템을 거치는 재진입은 비동기 전달과 결과 통지로 구성한다. 동기 재진입이 필요한 도구에는 시간 제한과 추적 식별자를 두고, 서비스 사이의 대기 시간과 중단을 함께 관측한다.

### 6. 격리·자격 증명·비용 통제는 호스트의 책임이다

상태 `수용(설계 의도)` · 시점 `단기` · 범위 TypeScript, Python

설계 의도

런타임은 모델과 도구를 연결하고 실행 의미를 제공한다. 도구 프로세스 격리, 비밀 정보 배포, 모델 제공자의 지출 한도와 조직별 사용 정책은 호스트가 적용한다.

호스트가 알아야 할 점

신뢰할 수 없는 도구는 별도 프로세스나 샌드박스에서 실행하고 최소 권한 자격 증명을 전달한다. 모델 어댑터에는 제공자 요청 한도와 취소 가능한 시간 제한을 적용하며, 실행 이벤트의 사용량과 실패율을 비용·운영 관측에 연결한다.

### 7. 세션 저널의 보존 기간은 호스트가 정한다

상태 `수용` · 시점 `규모 확대 시` · 범위 TypeScript, Python

현재 설계에서 감수하는 내용

세션의 대화, 실행과 승인 작업은 한 저널에 함께 남는다. 업무상 수명과 법적 보존 기간은 호스트만 알 수 있으므로, 런타임은 자동 만료 시점을 정하지 않는다. `sessions.delete`는 해당 세션의 저널 전체를 삭제한다.

호스트가 알아야 할 점

호스트는 사용자 세션 종료, 로그아웃, TTL 만료와 감사 보존 요건을 함께 고려해 삭제 정책을 정한다. 삭제 실패를 재시도하고 영속 저장소에서 실제로 삭제되었는지 관측한다.

### 8. YAML 템플릿 경로는 구성 작성자를 신뢰한다

상태 `수용` · 시점 `단기` · 범위 TypeScript, Python

현재 설계에서 감수하는 내용

렌더러는 구성 로딩 시 읽은 템플릿만 사용하고 정적 `include`의 절대 경로와 `..`를 거부한다. YAML에 직접 선언한 템플릿 경로는 절대 경로와 `..`를 사용할 수 있다(`spec/goondan.md:310-328`). 따라서 구성 작성자는 호스트 프로세스가 읽을 수 있는 파일을 템플릿으로 지정할 수 있다.

호스트가 알아야 할 점

구성 작성자를 신뢰할 수 없는 호스트는 구성을 제한된 파일 시스템과 별도 프로세스에서 읽거나, 구성 로딩 전에 선언 경로의 실제 경로가 허용 루트 안에 있는지 검사한다. 허용 경로 검사에는 심볼릭 링크 해석 규칙도 포함한다.

## 현재 보호 장치와 회귀 조건

| 위험 | 현재 설계와 근거 | 회귀 조건 |
|---|---|---|
| 여러 프로세스가 같은 세션에 동시에 기록해 이벤트가 사라진다. | 저장소가 세션당 임대를 제공하고, 런타임은 임대를 갱신하며 상실 시 실행을 중단한다. 모든 추가는 기대 머리 `expected`, 단조 증가하는 펜싱 토큰과 멱등적인 `writeId`를 사용한다(`packages/core/src/runtime.ts:339-438`, `packages/core/src/store.ts:71-190`, `python/goondan/goondan/runtime.py:644-810`). | 저장소 어댑터가 임대·조건부 추가·펜싱 검사를 서로 다른 비원자 연산으로 구현하거나, 런타임이 임대 상실 뒤에도 기록한다. |
| 승인 작업의 실행·완료 전달을 만료된 작성자가 계속 진행한다. | 승인 상태와 전달 상태는 같은 세션 저널에 기록된다. 세션 임대와 펜싱 토큰을 가진 작성자만 상태를 바꾸며, 복구도 새 임대를 얻고 저널을 재생한 뒤 수행한다. 완료 입력은 안정적인 전달 식별자로 중복을 판별한다(`packages/core/src/runtime.ts:339-438`, `packages/core/src/runtime.ts:2024-2082`, `python/goondan/goondan/runtime.py:644-810`). | 작업 상태를 저널 밖에서 바꾸거나, 복구·완료 전달이 세션 임대와 펜싱 검사를 거치지 않는다. |
| 저장 형식을 알 수 없는 런타임이 저널을 잘못 재생한다. | 모든 저널 이벤트에 형식 버전이 있으며 fold도 버전을 가진다. 알려지지 않은 비필수 이벤트는 `skippable`일 때만 건너뛰고, 스냅샷은 fold 버전과 상태를 함께 기록한다(`packages/core/src/fold.ts:266-317`, `python/goondan/goondan/fold.py`). | 이벤트나 스냅샷에서 버전을 제거하거나, 모르는 필수 이벤트를 묵시적으로 건너뛰거나, 새 작성자를 배포한 뒤 이전 읽기 전용 런타임의 호환성을 확인하지 않는다. |
| 같은 인스턴스의 실행 중 입력이 임의의 병렬 실행으로 들어간다. | 입력은 `(sessionId, instance)`의 대기열에 들어가며, 실행이 진행 중이면 다음 안전 지점에서 합류하고 실행이 끝났으면 다음 실행을 시작한다. | 대기열 소유권을 에이전트 선언 이름보다 넓게 공유하거나 실행별 임시 대기열로 분산한다. |
| 중단 제어기가 같은 세션의 다른 분기를 놓친다. | 세션은 진행 중인 실행 제어기 집합을 유지하고, 분기 실패와 `abort`가 해당 세션의 실행에 중단을 전파한다(`packages/core/src/runtime.ts`, `python/goondan/goondan/runtime.py`). | 세션마다 단일 실행만 저장하거나 실행 종료 시 제어기 집합 전체를 제거한다. |
| 두 호스트의 훅 컨텍스트와 식별자 의미가 달라진다. | 두 호스트는 `sessionId`, `turnId`, `instance`, `executionId`, `inputId`와 실행 원인을 같은 의미로 기록하고, 공통 실행 컨텍스트 위에 단계별 멤버를 추가한다(`spec/goondan.md`). | 한 호스트에만 공개 멤버를 추가하거나 식별자 범위를 바꾸고 규격과 양쪽 공통 사례를 함께 갱신하지 않는다. |
