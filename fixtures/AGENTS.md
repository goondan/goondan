# 공통 사례

이 폴더는 TypeScript와 Python 구현이 함께 통과해야 하는 공통 사례를 소유합니다.

- `conformance/`: 같은 YAML의 실행 의미를 검증합니다. 사례 형식과 러너 계약은 [`conformance/README.md`](conformance/README.md)를 따릅니다.
- `models/`: 공식 모델 어댑터의 요청 변환과 스트림 조립을 검증합니다. 사례 형식은 [모델 어댑터 규격의 공통 사례](../spec/model-adapters.md#공통-사례)를 따릅니다.

## 규칙

- `conformance/` 바로 아래의 모든 디렉터리는 사례이며 `case.json`, `expected.json`과 필요한 경우 `config/`를 가집니다.
- 모든 사례는 `spec` 필드에 근거가 되는 `spec/goondan.md`의 절 제목을 적습니다. 규격의 모든 `##`, `###`, `####` 절은 하나 이상의 사례가 인용해야 하며, 두 러너의 검증 범위 테스트가 이를 확인합니다.
- 기대 값은 규격 문장에서 도출합니다. 한 구현의 출력을 기대 값으로 복사하지 않습니다.
- 두 언어는 모든 사례를 같은 기대 값으로 통과해야 합니다. skip, xfail, 언어별 예외 목록을 두지 않으며, 러너가 표현할 수 없는 사례는 `unsupported by <language> runner`로 실패합니다.
- 사례는 네트워크 없이 실행합니다. 실제 자격 증명, 사내 호스트와 게이트웨이 주소, 과금 코드를 넣지 않습니다. 모델 사례의 `apiKey`에는 임의 값을 씁니다.
- 오류 사례에는 결함을 하나만 둡니다.
- 연산, 실행 단계, 관측 영역을 추가하거나 바꾸면 `conformance/README.md`와 두 러너를 같은 변경에서 갱신합니다.
- 실행 의미가 바뀌면 규격, 두 구현과 사례를 같은 변경에서 맞춥니다.
