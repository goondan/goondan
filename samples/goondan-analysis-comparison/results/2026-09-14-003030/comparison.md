모델 요청과 실험 전체의 자동 시간 제한은 제거한 상태입니다. 두 구성은 동일한 430개 소스 파일의 복사본, 공통 사용자 입력과 공통 분석 정의를 사용했습니다. 조사가 끝난 뒤 소스 파일의 해시를 대조했으며 변경된 파일은 없었습니다. 각 최종 출력은 해당 구성의 마지막 에이전트 응답과 일치합니다.

## 읽기 쉬움과 사실 보존

구현과 보고서 생성에 참여하지 않은 `gpt-5.6-sol` 검토자가 두 결과를 비교했습니다. 조건을 알고 수행한 검토이며, 익숙한 용어, 친절한 말투, 순차적 논지 전개와 정보 밀도를 각 5점으로 평가했습니다.

편집본은 `SSOT`, fixture, harness, port 같은 용어를 처음 등장할 때 풀이하고, 세부 실행 단계보다 먼저 전체 순서를 보여 줍니다. 단일본은 정보를 더 압축해서 전달하지만 한 문장과 목록 안에서 여러 동작을 함께 설명하는 부분이 많았습니다. 편집본도 약 2만 자로 길며, 일부 읽기 순서 안내와 연결 문장은 더 줄일 여지가 있습니다. 문장 사례와 기준별 점수는 [전달력 평가](readability-review.md)에 있습니다.

편집 단계의 보존 여부는 직렬 구성 내부에서 분석 에이전트가 작성한 원문과 편집 결과를 직접 비교했습니다. 새 조사나 기술 사실·근거 경로 추가, 결론 강도의 변화, 불확실성의 소실은 발견하지 못했습니다. 이는 원분석의 모든 기술 주장을 저장소와 다시 검증했다는 뜻은 아닙니다. 세부 결과는 [편집 보존 평가](fidelity-review.md)에 있습니다.

## 해석 범위

각 조건을 한 번씩 실행한 탐색적 비교입니다. 두 분석은 각각 생성되므로 내용과 도구 호출 횟수가 다릅니다. 따라서 약 118초의 시간 차이 전체를 편집 단계의 추가 비용으로 해석하거나, 최종 보고서의 모든 차이를 편집 효과라고 단정할 수 없습니다.

분석 프롬프트는 도구 호출을 12회 이내로 제한하도록 지시했지만 실제 호출은 21회와 19회였습니다. 이 조건은 프롬프트 지침이며 런타임의 강제 상한으로 구현하지 않았습니다. 두 구성에 같은 지침을 사용했다는 범위에서 비교합니다.

앞선 실행의 실행 횟수 초과, 요청 시간 제한 오류와 시간 제한 제거를 위한 중단 기록은 각각의 실행 디렉터리에 보존했으며 품질 비교에서 제외했습니다. 터미널의 진행 상황 표시 방식은 이번 평가에 포함하지 않았습니다.

실제 사용한 구성과 프롬프트는 [configs](configs), 입력은 [input.txt](input.txt), 실행 조건과 원자료 위치는 [metadata.json](metadata.json)에 있습니다. 재사용할 구성은 [단일 구성](../../single/goondan.yaml)과 [직렬 구성](../../edited/goondan.yaml)입니다.
